## 0.5 调研依据（外部文献，2026-10-31 检索）

方案里的每个机制都不是我发明的，逐条对应已发表做法：

| 本方案机制 | 外部依据 | 采用的具体点 |
|---|---|---|
| 动态凑批（替代固定窗口） | NVIDIA Triton 动态批处理文档 | `max_queue_delay` 是**上限**而非固定等待：能凑成目标批量就立即发，凑不成才等到上限；另有 `preferred_batch_size`（凑到优选规模立刻发）。本方案对应 `BURST/QUIET/SOLO/MAX_WAIT` 四值，并补「优选规模即刻发」 |
| 心跳与监视者不阻塞 | systemd `WatchdogSec` + `sd_notify(WATCHDOG=1)`；Erlang/OTP supervisor 设计原则 | 心跳周期取超时的一半（`WatchdogSec/2`）；监督者只做启停与重启，绝不阻塞在被监督进程上；重启必须设强度上限（`intensity`/`period`），否则崩溃循环会拖垮监督者 |
| 证据可验证（而非自述） | SLSA v1.2 Build Provenance / in-toto Attestation | 证据=对 `subject`（内容摘要）的 `predicate`；`externalParameters` 视为不可信、必须下游复核，`internalParameters` 才可信；验证=重算摘要 + 校验构建者身份 + 套策略 |
| 审定轮次有界 | Google 现代代码评审实证研究（900 万次评审） | 小改动、单审阅者、80% 以上最多一轮往返；改动越大意见质量越低、延迟越高。LLM 评审实证（SWR-Bench）：最好的 LLM 评审 F1 仅 19.38%，主要被误报拖累；多轮聚合可提升但仍是「辅助审阅者」而非裁决者 |

由此得出三条对本方案最关键的外部结论：

1. **「每次审计意见都是阻断项」在统计上站不住**：LLM 评审的精度很低，若把它的每条意见都当阻断，就是无限回退——这正是我十一轮被否的机制。
2. **凑批的等待必须是上限而不是固定值**，且一旦凑够目标规模要立刻发。
3. **心跳缺失才是「卡死」的定义**：只要心跳与状态面持续更新，慢不等于卡；反过来，没有心跳的长命令即使最终成功，也应被判为不可观测。

## 1. 观测面：监视者绝不等待（L-WATCHER-NEVER-WAITS）

### 机制
- 一切可能超过 30 秒的工作，只准以 `scripts/longrun.sh <名> -- <命令>` 启动。该脚本 1 秒内返回，任务放进独立会话（`setsid`），并建立状态面：
  - `state.json`：`name/pid/status/rc/started_at/ended_at/elapsed_s`
  - `heartbeat`：每 5 秒覆盖写 `<epoch> alive|gone`
  - `out.log`：子进程全部输出
- 一切观测只准用 `scripts/probe.sh <名>`：只读三个文件，2 秒内返回，退出码 `0 运行 / 10 成功 / 11 失败 / 12 未启动 / 13 状态损坏`。
- 禁止：前台跑超过 30 秒的命令；禁止 `while` 轮询里再调阻塞命令；禁止以 `ps`/`pgrep` 作为唯一存活判据（`/proc/<pid>` 或心跳年龄）。

### 机器判据（可重跑）
```
sh scripts/longrun.sh demo -- sh -c 'sleep 5; echo ok'   # 打印 LONGRUN-STARTED，wall < 1s
sh scripts/probe.sh demo                                  # rc=0，hb_age_s ≤ 5
sleep 6 && sh scripts/probe.sh demo                       # rc=10，out 末行=ok
```
实测：`launch_ms=56`；`probe` 在 1 秒处 `rc=0`、6 秒处 `rc=10` 且 `status=done`。

### 已知例外（必须具名）
- `sibyl_audit` / `sibyl_consult` 是**阻塞式 MCP 工具**，一次 200–500 秒。新规：每回合最多一次，必须在台账记录耗时；不得放进流水线或循环。
- 长期替代：优先用 `sibyl_review`（返回 receipt）配 `sibyl_status(runId)` 轮询；能力待验证，验证通过后作废阻塞用法。

## 2. 调度面：并发、估算、动态凑批

### 机制
- 两道并行：模型道（`candidate`/`judge`）上限 1；便宜道（`seed`/`plant`/`clean`/`harvest`/`ledger`/`query`）上限 4。上限可由环境变量调整，默认值写在代码常量里。
- 复杂度估计：按 `stage` 与 `item` 的历史耗时中位数给每个作业一个预估；预估只用于排队与凑批，不作为预算承诺。
- 凑批改为动态：5 秒内到达多于 2 件即判为「突发」，等到 1.5 秒静默再发；否则等 1 秒即发；硬上限 20 秒。窗口参数来自作业时长分布实测（median 0.58s、p90 106s），不是拍脑袋。
- 预算：每世代记录 `items/receipts/seconds/disk_bytes`，超预算即在报告中标记。

### 机器判据
```
parse runner.log → 并发峰值 ≤ (1 模型 + 4 便宜)；单件唤醒占比 < 20%
budget.jsonl 每代一行，字段齐全
```

## 3. 发现面：不写死任何机具

### 机制
- `scripts/discover-tools.mjs` 三层发现：
  1. 机主登记表（`$ABATHUR_TOOL_REGISTRY` JSON）—— 优先级最高；
  2. 配置里的插件条目 → 包目录 → `package.json` 的 `bin`；
  3. 能力自述（`--describe`）或 `--help` 推断，推断来源标 `INFERRED`。
- 发现只产生候选，不自动选。使用某机具必须由机主具名登记；未登记时输出 `UNDISPATCHABLE` 并 `rc=2`（fail-closed）。
- 代码与规则文本中不得出现具体机具名或路径；只引用环境变量与登记表字段。
- 跨插件复用的依据是**包声明的接口**（`package.json` 的 `bin`、`capabilities`）与**文档化的 CLI**，不是包名（实测同一包有 5 个别名）。

### 机器判据
```
node scripts/discover-tools.mjs --capability gate.publish   # 返回候选或空 + rc≠0
ABATHUR_GATE_CMD=/bin/true sh scripts/publish-precheck.sh   # rc=0
env -u ABATHUR_GATE_CMD sh scripts/publish-precheck.sh      # rc=2，打印 UNDISPATCHABLE
```

## 4. 方法论替换：从「说服审计者」到「断言全绿」

### 新规则（取代「写纸—送审—改纸」循环）
1. **断言即事实**：任何准入声明必须写成可执行断言（命令 + 期望 rc/输出 + 来源路径），文档只是断言的索引。文档中出现无断言支撑的数字，一律视为债，不得进门。
2. **一次覆盖审，不做逐字循环**：同一工件最多两轮独立审。第一轮只回答「断言集是否覆盖关键面」；第二轮只复核上一轮指出的**覆盖缺口**是否补齐。此后任何文字意见登记为文档债，**不阻断晋升**。
3. **禁止无限回退**：审计方指出的是「缺什么断言」，不是「句子怎么写」。若审计意见无法转成断言，登记为意见，不重写文档。
4. **固定预算**：每世代模型调用、墙钟、审计轮次都有上限；超限即停并报告，不允许无限打磨。
5. **外部锚优先**：机器结论必须有非本仓自写的锚（引擎会话库、哈希链、外仓回执）。锚不成立时结论标 `UNANCHORED`，不得称通过。

### 与现有产物的关系
- 已被十一轮审计打磨的 G66 提名页：冻结为历史证据，不再迭代。
- G67：改为「断言集 + 索引页」，断言集可一键全跑。
- 今后世代一律用新形态生成，不再手写叙述。

### 机器判据
```
python3 loop/assertions.py check <gen>     # 全部断言 rc=0 → 绿；否则失败项列出
python3 loop/assertions.py list <gen>      # 断言条数、覆盖的阶段/信号
```

## 8. 具名例外与残余风险（不假称闭合）

1. 阻塞式 MCP 审计仍是例外，未从根上异步化。
2. 所有闸输入仍是同 uid 可写文件，只挡候选、不挡操作者。
3. 判卷是 LLM，不可约权威；`PERFORMANCE-ONLY-IN-LOOP`、`MODEL-DIVERSITY-PENDING` 继续挂。
4. 网络未隔离（候选需连本机推理端点）。
5. 复杂度估计是历史中位数，不是解析式估算；冷启动阶段会失准。
