# Release 0.5.7 — ops integrity Tier 0

gate: PASS

## 为什么发这一版

`ops` 已经在本机通过审查和测试，但 0.5.6 的 npm 包里没有它。对一个产品来说，
“本机能跑、装完没有”不算交付。这一版把 Tier 0 的本地完整性检查真正装进包：

- `abathur ops init`：生成执行契约和 hash 链 genesis；
- `abathur ops seal`：契约修改后追加绑定；不 seal 就审计失败；
- `abathur ops audit`：本地检查，`LOCAL-PASS` / `FAIL` / `UNVERIFIED` 三态；
- `abathur gate run`：只在项目有 `ops/execution-contract.json` 时运行 ops；
- 报告带 `claim.anchored=false`、限制、`coverage`、`excepted_count` 和稳定摘要。

这一版不声称能防同 uid 伪造，不声称是沙箱，也不声称已做外部锚定。

## 修了什么

- 契约与仓库对账：检测到但未声明 → `SURFACE-MISSING`；声明但未检测到 →
  `SURFACE-STALE`；声明路径不存在 → `SURFACE-PATH-MISSING`。
- `pyproject.toml` 只读 `[project.scripts]`，不再把 `name`、`requires-python`
  当入口。
- 例外必须有 `primitive`，有效期最长 90 天；豁免在报告中可见。
- 报告摘要排除 `generated_at`，同一批文件可复现。
- 退出码：0 本地通过，1 失败，2 未验证，3 操作错误，70 内部错误。
- `coverage` 披露排除目录、符号链接、深度上限、扩展名和语言缺口。
- ledger 是 hash 链：`init` 写 genesis，`ops seal` 写契约绑定；最新绑定与
  当前契约哈希不一致即 `LEDGER-CONTRACT-MISMATCH`。
- `gate run` 只在项目有契约时跑 ops；未采用者零影响。

## 怎么发

沿用 OIDC 通道。每条命令都显式带工作目录：

```sh
cd /home/lab/workspace/harness/Abathur && git show archive/v1-final:scripts/release-lease.sh > /tmp/abathur-release-lease.sh
cd /home/lab/workspace/harness/Abathur && sh /tmp/abathur-release-lease.sh acquire v0.5.7 abathur
cd /home/lab/workspace/harness/Abathur && git push origin main
cd /home/lab/workspace/harness/Abathur && git push origin v0.5.7
cd /home/lab/workspace/harness/Abathur && sh /tmp/abathur-release-lease.sh release
```

GitHub Actions `publish.yml` 用 OIDC 发布并生成 provenance。等 `Publish` 成功后再安装：

```sh
cd /home/lab/workspace/harness/Abathur && npm install -g @tachikomagundam/abathur@0.5.7
```
