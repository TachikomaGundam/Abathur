# Release 0.5.6 — dispatch boundary codified

gate: PASS

## 为什么发这一版

0.5.5 已经把 `tools/wave_engine` 留在仓库、排除出 npm 包，但这个边界只靠一次
人工审查和 `package.json.files` 的空白维持。任何人把 `tools` 加回 `files`，
或让 `__pycache__` 进入 tarball，都不会有本地闸门拒绝。

西比拉对“是否把派单方法抽象进内核”的意见是 A：只把方法写成条令和规则，
不把 Python 派单器搬进 Node 内核。本版落实这个决定。

## 修了什么

- `docs/parallel-dispatch-doctrine.md`：新增“方法论边界”一节。派单条令是权威；
  `tools/wave_engine/wave.py` 是源码 checkout 里的参考实现，不是运行时依赖；
  npm 包不含 `tools/`，`kernel/dispatch` 不存在，运行时若重启必须另立宪章。
- `rules/registry.yaml`：新增 `P-DISPATCH-BOUNDARY-01`（class P，共 22 条）。
  检查命令为 `node --test test/dispatch-boundary.test.mjs`。
- `test/dispatch-boundary.test.mjs`：三条测试锁住包边界、发布 workflow 的
  tarball 守卫、条令中的边界声明。
- `rules/generated/RULES.md`：由 registry 重新生成。
- `AGENTS.md`：规则条数从 21 更新为 22。
