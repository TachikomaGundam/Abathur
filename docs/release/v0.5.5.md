# Release 0.5.5 — run-record trust, honest Q removal, on-demand candidate build

gate: PASS

## 为什么发这一版

0.5.4 安装后能正确识别仓库根，但四端闸门仍有三处只在文档里成立：

1. `readRunRecord` 只比较运行 ID，不检查记录来源和落点。一个同用户进程把任意
   JSON 放到任意路径，就能让 CLI 当成 launcher 记录接受。
2. `SURFACES.Q` 仍声明一个早已不存在的发布 checkout。`surface show` 不会报错，
   但任何按 Q 面写的代码都会指向空气。
3. 发布候选包没有可复跑的制件脚本。上一版靠手工 `git archive` + `npm pack`，
   数字无法从命令重新得到。

## 修了什么

- `kernel/surface/record.mjs`：记录必须位于 `/abathur-run.json` 或
  `runsDir()/<id>.json`，`origin` 必须是 `launcher`，`ABATHUR_RUN_ID` 必须存在且
  相等，签发 pid 必须仍活着。错误码分别是 `RUN-RECORD-UNTRUSTED`、
  `RUN-RECORD-MISMATCH`、`RUN-RECORD-EXPIRED`。
- `kernel/surface/index.mjs`：删除 `Q` 面。Q 面退役，不再以声明形式存在。
- `README.md`：新增 `Trust boundary (same-user)`，如实写明：记录是收据不是墙；
  cage 内只读，cage 外同用户可改写；链头防事故不防同用户。
- `scripts/release-candidate.mjs`：按 commit 构建，不打包工作树；在隔离临时目录
  运行 `git archive` + `npm pack`，记录 sha256、文件数、脏树标记；拒绝未知
  commit 和 evidence 根之外的输出目录；构建前自建 temp root。
- `test/release-candidate.test.mjs`：新增成功路径，强制使用全新 state 目录，
  防止 `mkdtemp` 的 ENOENT 回归藏在错误路径测试后面。
- `test/surface-record.test.mjs`：新增记录路径、来源、文件名、缺失运行 ID 四类
  拒绝测试。
- `test/surface.test.mjs`：断言 `SURFACES.Q` 不存在。
- `tools/wave_engine/wave.py`：manifest 的每格必须有 `cwd`，且 `cwd` 必须真实
  存在于 `allowed_roots` 内；路径比较用 `realpath`，防止符号链接逃逸；派单行
  自带 `cd <cwd> &&`；`done` 支持 `--expect-root`；回执里的相对路径按该格
  `cwd` 解析，不按监工目录猜。
- `AGENTS.md`：恢复仓级项目义务面，明确每条命令必须带显式目录。

## 怎么发

沿用 0.5.3 起的 OIDC 通道。每条命令都显式带工作目录；不要在别的仓库里执行：

```sh
cd /home/lab/workspace/harness/Abathur && git push origin main
cd /home/lab/workspace/harness/Abathur && git push origin v0.5.5
```

GitHub Actions `publish.yml` 用 OIDC 发布并生成 provenance。发布后安装：

```sh
cd /home/lab/workspace/harness/Abathur && npm install -g @tachikomagundam/abathur@0.5.5
```
