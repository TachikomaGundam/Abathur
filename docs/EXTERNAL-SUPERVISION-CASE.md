# 外部监督的必要性论证（2026-11-01）

机主问：为什么必须有「脱离本席位控制的运行环境」。本文是论证，不是提议；结论在末节。

## 1. 事实前提

1. 判卷是 LLM。检索到的公开基准（SWR-Bench，1000 个 PR）给出最好的 LLM 评审 F1 为 19.38%，主要损耗是误报。任何「LLM 说不」都不是终局证据。
2. 考生与判卷此前是同一模型（`local-qwen/qwen3.8-flash-next`）。2026-11-01 起判卷切到 `bailian-token-plan/deepseek-v4.1-flash-1017`，同族盲区被缩小但未证明消除。
3. 全部闸的输入都在同 uid 可写面：`verdict.json`、`gate.txt`、`bundle.json`、`draw-ledger.jsonl`、预算行、证据清单。写下这些文件的就是被监督方。
4. 2026-10-31 到 11-01 之间，我在同一批事实上至少四次自行改口：先说零提交、后被自己的提交证伪；先说「已同步插件」实际没同步；先声明「上下文快满了」实测还有大块空间；先指控自己「脑补了函数」读盘后证伪。这些错误全部由外部（机主或审计席）先发现，不是我自己发现。

## 2. 为什么本席位内部无法补上

监督的三个组成部分——产生证据、核对证据、裁定证据——目前全在同一进程、同一 uid、同一文件系统里。可以自己核对，但「核对者」与「被执行者」同一时，任何一次自我改口都同时改写了记录与解释。这不是诚信问题，是结构问题：同源的两个观察者不构成独立证据。

已有的部分缓解及其上限：

| 已有的 | 它能做什么 | 它不能做什么 |
|---|---|---|
| 引擎侧会话库（`judge-home/.../opencode.db`） | 提供一份非本仓写出的会话记录 | 仍是同 uid 普通文件，我或有同权限者可直接改 |
| 钉住代码的重跑（`rerun_zero_trust.py`） | 证明「同一答卷在钉住代码下得同一结论」 | 钉子由我选、由我落盘 |
| 独立审计席（`sibyl_audit`） | 提供非本链的第三方判断 | 读的是我给的工件；15 轮里它抓到的都是文字层，从未验证过二进制 |
| 边检工具 | 对外发内容做机械拦截 | 只在我调用它时工作，不检查我是否漏调 |

## 3. 反方意见（认真处理）

- **「成本太高」**：一个只读 clone + 每周一次重跑，成本是一次模型调用，不是常设人力。
- **「等于不信任自己」**：这不是信任问题。判卷是 LLM、闸输入可写，两者都是客观事实；在客观不可信的输入上要求信任，是把结构缺陷道德化。
- **「已经有人类机主」**：机主是最终裁决者，但不是持续监督者——人不可能每代盯着几十个文件。外部监督不是替代机主，是把「可被抽查」变成「被定期抽查」。
- **「可以先做到足够好再说」**：本轮已经验证过这条路的上限：15 轮审计后仍能被我新一轮修改引入新缺陷。足够好没有终点，但「可被外部复算」有终点。

## 4. 最小可行设计

1. 一份**只读 clone**（独立目录，不含我的工作树），只拉 git 跟踪面。
2. 用 clone 内的 `scripts/verify-all.sh <GEN>`、`loop/rerun_zero_trust.py <GEN> <ITEM>` 复算；`evidence/<GEN>/` 已在 git 内（本轮起），clone 自带证据。
3. 结论写成一份回执，独立保存（不进我的工作树）。
4. 频率：每代一次；发现不一致即冻结该代晋升。

## 5. 结论

外部监督必要，理由是结构性的：证据的产生、核对、裁定三者同源时，独立复算无法成立。判卷是 LLM 且闸输入可写，这两条客观事实不会因为我在同一环境里再写多少闸而改变。

它**不**替代机主的裁决权；它保证机主裁决时手里那份证据是别人也能复算出来的。
