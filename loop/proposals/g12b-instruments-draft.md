# 信任根顺序（议会史教训排序,不可打乱）：g12b-2（会话库保护）先于 g12b-3（锚验证器）——验证器的被验对象必须先有完整性锚,否则整层塌回声明（3710 原文:「在信任根处塌回声明层」）。

## g12b-1 证据账本与条目体 schema（仓：Abathur）
- 交付：MT 条目体 JSON schema（ledger_id/seq/kind/target/pre/post/atomic/ref/cmd/argv/output_sha256）+发号器+分叉/链序一致性校验器;桥接条目（跨账本因果）谓词。
- 验收：故障注入——拆账逃序、probe-A 背书 write-B、echo 伪探测、同前项分叉、seq≠物理序五用例全被校验器非零捕获;双跑噪声探针（同输入两跑差=0 或具名豁免）。
## g12b-2 引擎会话库完整性（仓：Sibyl/Abathur 会话库宿主——**总根,最优先**）
- 交付：会话库文件路径/mode/当期哈希入基线监视（对应 3710 会话库 MF-13:DB 读视图哈希随每次验证落 probe 入追加式账本）;DB 基线缺失→状态基线缺失路由（证据不足,不开新态）。
- 验收：事后改一条消息正文→视图哈希集合差命中;合法并发写不误伤（SQLite WAL 语义实测,双进程交错用例）。
## g12b-3 人类锚验证器（仓：Sibyl;依赖 g12b-2）
- 交付：在册比对器——账本内一切"人类签署/消息 ID+原文"声明对引擎会话库逐字核验+落 probe 收据;缺席期语义**必须带出口**（3710 死锁教训：无效 vs 唯一解锁的互斥,设计定稿前 oracle 预演"永久损坏"场景）。
- 验收：伪锚（抄 ID 改正文）命中;真锚通过;验证器自身进程死亡时路由=盲区账+人类终端工单,不死锁。
## g12b-4 归因比对器+附录A 机械化（仓：Sibyl）
- 交付：ref 移动归因（推送者身份/签名 vs 名册绑定）;附录A 包含性判据（回退差分路径集⊆报告指认工件集）的逐行核对命令入册。
## g12b-5 扫描器心跳+覆盖基线集合差（仓：Abathur graders/）
