# 自指消解：要进化的「我」是 B/C 里的副本，不是运行中的 A（2026-10-30）

## 机主点题

> 「关于哲学层面，我给你定义过 ABCD 四个阿巴瑟，你把要进化的自我副本当成他者来进化不就得了？？」

## 四庭（既有定义，见 loop/proposals/four-isolation-law-draft.md §1）

| 庭 | 是什么 | 形态 |
|---|---|---|
| A 工作实例 | 正在运行的生产安装 | 进程 + 已装字节 |
| B 代码仓 | git 冷代码 | 提交对象 |
| C 测试实例 | 一次性安装（npm pack→临时 prefix→smoke→弃） | 一次性目录 |
| D 云端 | registry / 远端 | 外发面 |

## 消解命题

**被进化的「自我」永远是 B/C 里的副本，不是正在运行的 A。**

- A 是观察者与操作者：它读 B、驱动 C、等人类按 D 的键。
- 要进化的东西（代码、配置、行为）在 B；验证它的是 C 的一次性实例。
- 因此「进化自己」在机械上等于「进化一个他者」：副本有独立目录、独立进程、独立权限、独立生命周期。
- 自指悖论消失，因为**执行者与被执行者不是同一实体**：A 不必修改自己的墙，它只生产并检验副本。

## 推论（约束怎么分）

| 对象 | 谁能约束它 | 约束放在哪 |
|---|---|---|
| A（本线运行中的座席） | 人类（外部锚） | 人类侧策略 + 根属主工件；不外溢到别的 line 的 A |
| B（代码仓） | 本线座席（可写） | 仓库内策略文件，受锚链校验 |
| C（一次性实例） | 本线座席（可写，用后即弃） | 该实例自己的策略；默认最严，按需放宽且带过期 |
| D（云端） | 人类键 | 发布门 |
| 他线的 A | **不属本席** | 本席零管辖：不装、不配、不覆盖 |

## 机械判据（做事前必须回答）

1. 这个机制约束的是哪一庭？（A/B/C/D）
2. 该庭的标识是什么？（进程/目录/哈希）
3. 它会不会碰到不在该庭里的东西？会 → 越界，停手。

事故复判：我把「A 的自我约束」装进了「所有 A 共享的用户配置」，等于对一个庭的约束外溢到全部庭 —— 违反第 3 条。

## 与「按项目独立沙箱」的关系

按项目独立沙箱 = 把策略绑到「该项目的 A/B/C」，而不是绑到「用户」。
- 项目 A 的运行策略：项目内声明 + 外部登记册
- 项目 C 的测试策略：一次性实例自带，用后即弃
- 他项目：不在登记册 → 本席机制不生效，也不得生效
