# 提案：按进化项目独立沙箱，权限按需配置（机主建议，2026-10-30）

## 来源

机主建议（逐字）：「针对每个进化项目独立设置沙箱，按需配置权限。这个建议不构成生产输入，届时你先送西比拉系统审议后再做决定。」

## 事故背景（为什么需要这条）

本席把「约束自己」的 bwrap 沙箱装进了 opencode **用户级**插件目录，导致该用户下所有产线会话的 bash 都被包裹：docker 套接字消失、npm registry 不可达、本机模型代理不可达。同一错误的第二个实例：文件工具策略（只放行工作区）同样装在用户级，使本席连自己蜂群产出的 `/home/lab/.sibyl/**` 都读不到。

共同病根：**没有主体谓词**。机制装在了「所有座席共享的宿主配置」上，而不是「某个项目」。

## 提案

### 1. 沙箱随项目走，不随用户走

- 策略文件放在**项目仓**内：`<repo>/.abathur/sandbox.json`。
- 插件放在**项目仓**内：`<repo>/.opencode/plugins/sandbox-bash.js`（opencode 只在该项目加载）。
- 用户级目录不再放任何约束类插件。

### 2. 主体谓词（不可伪造的绑定）

插件只在该项目加载，且策略文件必须与插件同仓。加载时断言：
- `policy.project` 字段 == 项目根目录名 + git 仓库远端/根路径哈希；
- 策略文件与插件均在工作区内（不在用户配置目录）；
- 两者哈希记入运行日志，每次调用输出一行（可机检）。

只有三者同时成立才启用沙箱；否则不生效并记录一行 `SANDBOX-SKIP reason=...`（不报错，避免误伤）。

### 3. 权限按需（默认全拒）

`sandbox.json` 字段（缺省=最严）：

| 字段 | 缺省 | 说明 |
|---|---|---|
| `network` | `none` | `none` / `allowlist`（逐条 host:port，注明用途与失效后果） |
| `mounts` | `workspace` 只读写 | 追加只读挂载（如工具链、venv） |
| `devices` | 空 | GPU 等按需 |
| `limits` | 保守值 | nproc/vmem/fsize |
| `mask` | 日志、密钥目录 | 一律遮蔽 |

每条放宽都必须写「为什么需要」与「放宽后新增的风险」，写进策略文件本身，随 git 留痕。

### 4. 爆炸半径测试（发布前必跑）

标准形态：
1. 在 A 项目（启用沙箱）跑 `probe.sh`：断言网络断、docker 不可达。
2. 在 B 项目（未启用）跑同一 `probe.sh`：断言**不受影响**（网络通、docker 可达）。
3. 断言两边的 bash 包裹形态不同（日志中的 `tier=` 行）。
4. 任一断言失败＝阻断发布。

### 5. 迁移顺序

1. 解绑：把用户级两个插件移出（`sandbox-bash.js`、`sandbox-tools.js`），恢复全机正常。
2. 重建：在需要的项目仓内各放一份项目级插件 + 策略。
3. 证明：跑爆炸半径测试，把回执写进对应项目台账。
4. 防复发：发布检查表新增一行「约束类插件只允许出现在项目级目录」。

## 请评审席攻击

1. 项目级插件是否真的只在该项目生效？若某项目的 `opencode.json` 显式引用用户级插件，如何防止绕过？
2. 主体谓词（项目名+路径哈希）是否可被改写策略的一方伪造？需要什么额外锚（git 提交哈希、root 侧登记）？
3. 「按需放宽」会不会在实践中退化成「一路放宽」？需要什么机械闸？
4. 爆炸半径测试如何在不干扰他席作业的前提下自动执行（他席可能正在跑长任务）？
5. 同一台机器上多个项目同时启用沙箱时，资源（/tmp、ulimit）如何隔离？
