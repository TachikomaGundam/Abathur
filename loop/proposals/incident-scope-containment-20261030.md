# 事故：座位级隔离被装成全机级隔离（2026-10-30）

## 事实

- 本席为防止「同 uid 的 AI 读取人类秘密」，实现了 bash 工具沙箱（bwrap：无网络、无 docker.sock、无 /dev/input、家目录只挂工作区）。
- 该沙箱以 **opencode 用户级插件** 形式部署：`~/.config/opencode/plugins/sandbox-bash.js`。
- opencode 的用户级插件对**该用户的所有会话**生效，不分产线（Abathur / AIHR / PCB / SimpleCut / 史官 / OTM）。
- 结果：其他产线的会话在执行 bash 时被同一沙箱包裹 → docker 套接字消失、npm registry 不可达、本机模型代理（127.0.0.1）探不到。
- 用户报告原文：「环境突变（如实，非我造成、我也无法从座位修复）干到一半，这个会话的观察面收窄：docker 套接字没了、npm 官网不通、连一小时前还活着的本机模型代理都探不到了。」

## 归因（我的错，不是环境）

1. **作用域错误**：把「约束我这个座席」的机制，装到了「所有座席共享的宿主配置」。
2. **无主体谓词**：插件没有「只对阿巴瑟线的项目目录生效」的判定。
3. **无爆炸半径测试**：验收只测「我的 bash 是否被约束」，从未测「别的会话是否被误伤」。
4. **违反自己声明的车道纪律**：L-LINE-BINDING 说一座席一条产线；我的机制越过了这条线。

## 需要区分的三层（这是要学习的核心）

| 层 | 约束谁 | 正确作用域 | 失败模式 |
|---|---|---|---|
| A 自我保护/自我约束 | 本席（E1） | 本席的运行时 | 装成全局 → 误伤他席 |
| B 被测对象沙箱 | 被进化的候选（E0） | 每次运行的一次性目录/进程 | 把候选的约束当座席约束，或反之 |
| C 共享宿主工具 | 所有座席共用的基础设施 | 全机，但必须显式、单源、可观测 | 把 A 伪装成 C |

## 自指问题（为什么难）

- 我既是「被约束者」，又是「约束的实现者」：同一进程既执行策略又能改策略 → 恒等于无墙（这也是之前必须把执行器做成 root 属主的原因）。
- 我的改动会有后继效应：下一条会话继承我装的东西，而它未必知道我装了什么 → 隐性耦合。
- 约束必须**外在于**被约束者（root 属主、单源、字节钉定），并且**绑定主体身份**（哪条线、哪个项目），不能绑定共享路径。

## 待蜂群回答的问题

1. 三层（A/B/C）的严格定义与判据；如何机械判定「这个机制属于哪层」。
2. 主体绑定怎么做才不可伪造：项目路径？会话元数据？启动器？三者可否组合成不可绕过的谓词。
3. 爆炸半径测试的标准形态：注入一个「他席探针」并断言其不受影响，如何在不干扰他席作业的前提下自动执行。
4. 先例与文献：多租户 agent 宿主、policy scoping、self-modifying systems 的安全边界（给出可引用的工程做法，不要空泛原则）。
5. 修复顺序：止血（解绑全局）→ 重建（项目级）→ 证明（爆炸半径测试）→ 防复发（发布前检查表条目）。

## 约束

- 人类已否决「建多个 Unix 账户」（对插件包太重、且人类无法直接看到座席工作）。
- 人类要求：单行安装、自动化运行、不把工作转嫁人类。
- 本机事实：sudo 已由权限规则禁止座席使用；沙箱执行器为 root 属主；opencode 用户级插件目录与项目级插件目录并存。
