## WHAT 3c6bbf9 BROKE
It flipped the fixture case in openBenchAdapter (run-bench.ts) from
`includeVal: true` (unconditional, pre-regression baseline 1d7a629^) to
`includeVal: opts.includeVal === true` (default false) while benchTarget still
iterates EVERY unit — train AND val. Any default `abathur run` on a val-bearing
fixture genome therefore died at the FIRST val unit, mid-bench, after spending
probes/reset/seed budget and before any generation row: SC4 (one bounded
generation on the shipped fixture genome) and T7 (val-regression nomination
gate, which REQUIRES val replicates, plan lines 125-132) unreachable on the
default path. 285/285 stayed green because no loop-level test benched a
val-bearing fixture genome without the flag (blind spot: historian-genome.test
only ever DRY-RUNS fixture genomes — dry-run returns before any bench).

## FIX (design: split the conflated axes — BENCHING AUTHORITY vs PATH EXPOSURE)
- src/bench/fixture.ts: FixtureAdapterOptions gains `loopValAuthority` (run/score
  val WITHOUT touching the manifest); gateVal now takes
  `valRunAllowed() = includeVal === true || loopValAuthority === true`;
  scenarioManifest() stays gated by includeVal ALONE (exposure unchanged);
  header + docs rewritten to the two-axis truth.
- src/core/evolve/run-bench.ts: `const LOOP_VAL_AUTHORITY = true` (comment cites
  plan 117-124/125-132/SC4 + this regression); benchTarget ALWAYS passes
  loopValAuthority to openBenchAdapter and forwards includeVal (exposure) only
  when the operator flag is on. graft-rebench's two benchTarget calls inherit
  authority automatically (same selection gate).
- src/bench/fixture-support.ts: gateVal(unit, allowVal) — refusal MESSAGE kept
  verbatim (pinned by /--include-val/ regexes); hint rewritten honest (direct
  adapter consumers still default-deny — todo-6 invariant, bench-fixture AC(B)
  untouched).
- src/core/evolve/run-loop.ts + src/commands/run.ts: includeVal docs now state
  EXPOSURE semantics + always-bench truth (no lying sentences). README grep:
  contains no --include-val text ⇒ untouched.
- WHY NOT `includeVal ?? true` at the loop (the task's fallback reading): the
  single option also drives buildManifest exposure ⇒ the loop would ALWAYS leak
  val ids/paths into every sandbox manifest (mutator-facing todo-6 violation,
  pinned by include-val.test.ts factory-default + bench-fixture AC(B)) and the
  CLI flag would be a pure no-op on run. The split makes --include-val honest:
  off = val benched-but-opaque (matrix rows present, manifest aliases only);
  on = same bench PLUS val ids/paths exposed.
- Toy fail-closed guard from 3c6bbf9 KEPT verbatim (run-loop.ts) + both of its
  tests kept (include-val.test.ts, run-loop.test.ts CLI wiring).
